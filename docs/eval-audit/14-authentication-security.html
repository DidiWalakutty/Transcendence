14. Authentication Security

✅ PASS

The repository supports a "Yes". Keep it that way. · audited 2026-09-18 · branch main @ 2143958

better-auth 1.6.27 handles signup/login; passwords are hashed with scrypt (N=16384, r=16, p=1, 64-byte key) and a random 16-byte salt, stored as salt:hash in accounts.password. The team must be able to say that sentence.

What the evaluator is asked

Does the user management system provide secure authentication?

  • Email and password signup/login
  • Properly hashed and salted passwords
  • Ask the team to explain their password security implementation.
  • Passwords must never be stored in plain text. The team should be able to explain their hashing/salting approach.

Red flags

mediumPassword reset link is only logged, never e-mailed

auth.instance.ts → sendResetPassword does logger.log('Password reset link … '). The /forgot-password page says "check your e-mail" but Mailpit stays empty; the link is in docker logs ft_transcendence_backend. Meanwhile NotificationService already sends four other e-mails — wiring the reset link through it is ~15 lines. If you leave it, do not demo forgot-password, or demo it with the log open and say why.

mediumWeak password policy

packages/schemas/src/fields.ts: passwordField = min(8), nothing else; no maximum (better-auth caps at 128 internally). aaaaaaaa is accepted. Acceptable for the sheet, but an evaluator testing "wrong formats" may raise it — have the answer: "length ≥ 8, scrypt makes brute force expensive, rate limit makes online guessing slow".

lowEmail verification is off

requireEmailVerification: false. Fine for a demo; say it is a deliberate choice because there is no real mail server.

lowAny logged-in user can list every user's e-mail

users.getUsers and users.searchUsers are ProtectedMiddleware (any account), and return the full userSchema (email, location, aboutMe, banned, role). Needed for the friends search, but a slimmer output schema (id, username, name, avatar) would avoid the "why can I see everyone's e-mail?" question.

What the code shows

The chain, file by file

  1. apps/backend/src/auth/auth.instance.ts: betterAuth({ emailAndPassword: { enabled: true }, plugins: [admin(), username(), twoFactor()] , secret: BETTER_AUTH_SECRET }), Drizzle adapter mapping to the users/sessions/accounts/verifications/two_factors tables.
  2. apps/backend/src/main.ts: app.use('/api/auth', toNodeHandler(auth)) mounted before the body parser (comment explains why).
  3. better-auth → @better-auth/utils/password (password.node.mjs): scrypt(password.normalize("NFKC"), salt, { N: 16384, r: 16, p: 1, dkLen: 64 }) with salt = randomBytes(16).toString("hex"); stored as `${salt}:${hash}`; verification recomputes and compares in constant time.
  4. Stored in accounts.password (packages/schemas/src/database.ts) — never in users. userSchema is built from users, so no API can return the hash.
  5. Sessions: random token in sessions.token, httpOnly cookie signed with BETTER_AUTH_SECRET; trustedOrigins = CORS_ORIGINS.
  6. Rate limiting on auth endpoints (better-auth default, BS-10: 3 sign-in attempts / 10 s per IP) + Nest ThrottlerGuard backed by Redis for tRPC.
  7. 2FA: TOTP with QR enrolment, backup codes, lockout counter (two_factors.failed_verification_count, locked_until).

Plain-English explanation to give (Corin: this is the one to memorise)

Hashing = a one-way blender: the password goes in, a fixed-size fingerprint comes out, and you cannot un-blend it. Salt = 16 random bytes mixed in before blending, different per user, so two people with the password "Qwerty123!" get different fingerprints and a precomputed table of common fingerprints is useless. scrypt = a blender deliberately built slow and memory-hungry (N=16384 rounds × r=16 blocks ≈ 16 MB) so guessing millions of passwords per second is not affordable. We store salt:fingerprint; at login we blend the typed password with the stored salt and compare fingerprints.

Prove it live

docker exec -it ft_transcendence_postgres psql -U transcendence -d transcendence \
  -c "select provider_id, left(password, 40) || '…' from accounts limit 3;"

Shows credential | 3f9a…:b71c… — hex salt, colon, hex hash. No plain text.
