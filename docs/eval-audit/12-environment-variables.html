12. Environment Variables

❌ FAIL as-is

On main right now this gets a "No". Fix before Saturday. · audited 2026-09-18 · branch main @ 2143958

The two checkboxes pass (.env ignored, .env.example present). The third does not: a TLS private key is committed, a tracked .env.development holds a real-looking auth secret and passwords, and the compose file inlines password defaults. The sheet calls this "immediate project failure".

What the evaluator is asked

Are credentials properly secured?

  • .env file exists and is in .gitignore
  • .env.example file is provided
  • No sensitive credentials in the repository

Any credentials, API keys, or sensitive information found in the repository (outside of .env) will result in immediate project failure.

Red flags

criticalTLS private key committed (caddy/certs/local-key.pem)

Fix without any key in git: let Caddy mint its own certificate. In caddy/Caddyfile replace tls /certs/local.pem /certs/local-key.pem with tls internal, drop the ./caddy/certs:/certs volume from compose, git rm --cached caddy/certs/*. Behaviour for the evaluator is identical (self-signed, one warning unless trusted). Keep scripts/generate-certs.sh for the mkcert-trusted variant on your own machine — it can write into the ignored folder and a second Caddyfile line can pick it up if present.

highTracked .env.development with a generated auth secret and passwords

Minimum: replace the UUID secret with the same obviously-fake string compose uses (dev-only-insecure-secret-change-in-production) and add a top comment "development defaults only, never used in production; real values go in .env (ignored)". Better: untrack it (git rm --cached, add .env.development to .gitignore) and have vp run dev copy .env.example when it is missing — but that changes the dev workflow the day before the eval; only do it if someone tests it.

mediumSame demo passwords in three places

.env.development, docker-compose.yml, and (implicitly) seed.ts. Decide the story: "demo accounts with documented passwords, needed so the evaluator can log in" — then say so in README §9 and do not call them secrets.

low.env.example says it should be ignored

Delete line 1. Add a comment per variable group. Delete the README "Known gap" paragraph.
