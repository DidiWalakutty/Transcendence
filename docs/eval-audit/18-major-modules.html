Real-time (2) — demo and the SSE question

Two browsers side by side: create an event in one, it appears in the other without reload; log in as a friend, the status dot turns green; send a chat message. Then use-event-stream.ts: heartbeat every 10 s, stale after 25 s, reconnect.

"Why not WebSockets?" — "The subject says WebSockets or similar. Our real-time traffic is server → client only (events changed, who is online, chat messages); the client sends through normal tRPC mutations. Server-Sent Events give us that push over the existing HTTPS connection, through Caddy, with automatic reconnect built into the browser, no extra port or protocol. We added a heartbeat so a dead connection is detected in 25 s, and handled graceful disconnects with AbortSignal (listen() in events.service.ts). If we needed client → server streaming, WebSockets would be the choice."

Advanced permissions and roles (2) — arguable

What exists: navigation.config.ts three roles; AdminMiddleware/ProtectedMiddleware; ownership checks; admin dashboard with user table, role select (user/admin), event table for all events; adminUpdateUserSchema.role: enum(['user','admin']). A strict evaluator gives 0; a reasonable one accepts three roles with distinct permissions. Adding a moderator who can edit/delete any event but not touch users is 2–3 h and removes the argument.
