The event-stream hook, from message to screen

A full walkthrough of use-event-stream.ts, with the module-scope clock, cache updates, and watchdog explained together.

1. What this hook connects

A hook is reusable React code that can use state, effects, and other hooks. useEventStream listens for backend event-change messages and updates the frontend query cache. It also returns connection flags so a page can show whether the stream looks healthy. It does not change the database or implement the network transport itself. 

Backend saves an event
  → subscription delivers a message
  → onData updates cached event data
  → React renders the new data

2. Imports and the two clocks

useState remembers a value and triggers rendering when it changes. useEffect starts work connected to a component lifecycle and can return cleanup code. useCallback keeps a function reference while its dependencies stay equal. useQueryClient supplies the cache manager, useTRPC supplies typed operation helpers, and useSubscription manages a tRPC subscription. 

const STALE_AFTER_MS = EVENT_HEARTBEAT_INTERVAL_MS * 2.5;
const WATCHDOG_INTERVAL_MS = 5_000;
let lastMessageAt = Date.now();

The shared heartbeat interval is 10,000 milliseconds. The stale threshold is therefore 25,000 milliseconds. The watchdog checks every 5,000 milliseconds. Underscores in numeric literals only improve readability: 5_000 and 5000 are the same number. Date.now() returns the current time in milliseconds since the Unix epoch; subtracting two such values measures elapsed time.

3. Why lastMessageAt is at module scope

Module scope means outside the hook function, at the top level of this JavaScript module. Its value survives one component being removed and a new instance being created, as long as that module instance remains loaded.

Storage Survives an ordinary rerender? Survives a component remount?
A plain local variable initialized in the hook No, its initialization runs again No
useRef value Yes No
This module-level variable Yes Yes, within the same module instance

A rerender updates an existing component. A remount destroys one component instance and creates another. The outage bug involved repeated remounts. With a ref initialized to the current time, every remount restarted the silence measurement. Remounting every few seconds could keep the apparent silence below 25 seconds indefinitely. 

Backend stops sending at time 0.
Component remounts at 5, 10, 15, 20 seconds.
A newly initialized ref would repeatedly forget time 0.
Module-level storage can retain the earlier timestamp.

This is a tradeoff, not a universal rule to replace refs with globals. All hook instances using this loaded module share the timestamp. A message received by one can refresh the clock seen by another. A full page reload resets it, and separate browser tabs do not share it. The status effect later in this file can also reset the timestamp.

4. patchList changes an array without fetching

const current = events ?? [];
return remove
  ? current.filter((item) => item.id !== event.id)
  : current.map((item) => (item.id === event.id ? event : item));

events ?? [] uses an empty array only when events is null or undefined. The ternary expression chooses between two branches. When remove is true, filter keeps every item with a different ID. Otherwise map replaces the matching event and keeps other items. Both operations produce a new array, which is suitable for a cache update. Neither inserts a previously missing event nor sorts the result.

(item) => ... is an arrow function passed as a callback. === compares without type conversion; !== checks strict inequality. The function return type EventDto[] means an array of event objects.

5. Hook options, state, and query keys

options?: { onlyOrganizerId?: string } means the entire options argument is optional, and its organizer filter is optional too. The hook stores a local boolean stale for rendering. This is separate from whether a TanStack Query cache entry is stale.

The listing key identifies the family of general event-list queries. Different sort orders can have separate matching cache entries. The My Events key identifies the organizer list. The hook works with generated keys instead of inventing unrelated strings.

refetchLists invalidates these two query groups. Invalidation marks cached answers outdated and normally refetches active eligible queries. Inactive entries can refresh when used again. The function uses void because it intentionally does not await the returned promises. Its name describes the aim; calling it does not mean every network request has already finished.

The dependency array [queryClient, listingsKey, myEventsKey] tells useCallback when to replace its stored function reference. useCallback does not call the function by itself.

6. What subscriptionOptions and onData do

trpc.eventCreation.onEventChanged.subscriptionOptions(undefined, {
  onData: (change: EventChangedDto) => { /* ... */ },
})

The first argument is undefined because this subscription has no input payload. The second argument contains callbacks. onData runs when a message arrives. Every message, including a heartbeat, updates lastMessageAt and sets stale to false.

The early return for a heartbeat is important. Heartbeats carry only an action, with no event object. After that branch, TypeScript can narrow the message type to a created, updated, or deleted message, each of which has an event. 

const mine =
  !options?.onlyOrganizerId || change.event.organizerId === options.onlyOrganizerId;
const removed = change.action === 'deleted';

mine is true when no organizer filter was supplied or the message belongs to the requested organizer. This limits My Events cache updates. It is a frontend filter, not a backend authorization check. General public-list updates still happen.

7. Why created takes a different path

A new event has no existing list position to replace. The server owns the query sorting and can use database fields that are not all present in EventDto. The hook invalidates lists so the server can return the correct placement. This request is triggered by a pushed message; it is not regular polling for new events.

An update usually has an existing row, so the hook replaces that row. A deletion removes it. setQueriesData patches matching general-list entries, including cached sort variants. setQueryData handles the particular My Events entry when mine is true.

Message General event lists My Events Event detail
created Invalidate Invalidate if mine Store event
updated Replace existing matching rows Replace if mine Store event
deleted Remove matching rows Remove if mine Remove cache entry
heartbeat No data change No data change No data change

The source comment overstates the sorting guarantee. Editing an event date can change its correct position in an upcoming list, but map replaces it in place. EventDto does contain date and time, although it lacks creation time and registration counts. The reason for refetching creation is server-owned ordering, not that the DTO has literally no sorting information. An update can leave ordering stale until a later refetch. Removing a detail cache entry also does not itself navigate the browser away.

8. The watchdog, step by step

if (Date.now() - lastMessageAt <= STALE_AFTER_MS) {
  return;
}
setStale(true);
lastMessageAt = Date.now();
reset();
refetchLists();
  1. The interval callback checks how long it has been since the last timestamp update. At 25 seconds or less, it does nothing.
  2. If the elapsed time is greater than 25 seconds, it marks the stream stale for the UI.
  3. It resets the timestamp so subsequent checks do not immediately repeat the reset every five seconds.
  4. It calls the subscription reset function to restart the stream.
  5. It invalidates the general event lists and My Events because messages may have been missed.

Detection is not exactly at second 25. The comparison is strictly greater than 25 seconds and the check runs periodically. In a normally scheduled browser it will happen on a later tick, often around 25 to 30 seconds after the last update; suspended or throttled tabs can take longer. The invalidation does not explicitly include every event-detail query, My Tickets, or ticket availability.

The effect returns () => clearInterval(watchdog). React runs this cleanup when the effect is replaced or the component unmounts. It prevents an abandoned component from leaving its interval running. The dependency array contains reset and refetchLists because the effect uses those functions.

9. The second effect and returned flags

When subscription status becomes pending, the second effect updates lastMessageAt, giving the newly active connection time to deliver a message. In this subscription API, pending is treated by this code as an active stream, not a query still waiting for its first result. The watchdog exists because that status alone may not reveal a silent broken connection. 

return {
  connected: status === 'pending' && !stale,
  reconnecting: stale || status === 'connecting',
  failed: status === 'error',
};

These are three booleans, not a single exclusive status value. For example, an error and a stale flag can make both failed and reconnecting true. A page must decide how it presents them. Updating these flags changes the UI; it does not itself change server data.

Questions to answer before reading the solutions

  1. How is a rerender different from a remount, and why did that matter to lastMessageAt?
  2. What happens to a created message for another organizer when onlyOrganizerId is supplied?
  3. If an event moves from next month to tomorrow, does patchList move it to the correct position?
  4. List every action taken when the watchdog sees more than 25 seconds of silence.
  5. Does resetting the stream replay every missed event or refetch every cache entry?

Answers and reasoning

  1. A rerender preserves the existing hook instance and its refs. A remount creates a fresh instance. A fresh timestamp on every remount could postpone outage detection indefinitely. Module scope retains a timestamp across those remounts but shares it across hook instances.
  2. The general event list is invalidated. My Events is not invalidated for that organizer filter. The event detail cache is still written.
  3. No. It replaces the object at its existing position. Correct date ordering needs sorting or a server refetch; this is a visible limitation of the current algorithm.
  4. Mark stale, reset the timestamp, restart the subscription, and invalidate the general and organizer lists. The interval keeps running until effect cleanup.
  5. Neither. The stream has no durable replay in this implementation, and refetchLists targets only two query groups. Refreshing selected queries helps recover current state, but is not replay of all missed messages.
